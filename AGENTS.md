Guidance for AI coding agents working in this repository.

## Project overview

Cribbage Grid is a browser-based card game built with **React 17** and bootstrapped with Create React App 4. Players compete on a 5×5 grid, placing cards to form cribbage hands across rows (P1) and columns (P2/CPU). The live app is deployed to GitHub Pages at <https://mgifford.github.io/cribbage-grid>.

Key features:
- Single-player vs CPU (adjustable difficulty via softmax-weighted AI)
- Local two-player (pass-and-play) mode
- Online two-player via WebRTC / PeerJS (no game server required)
- Accessibility: `@axe-core/react` runs in development; semantic HTML, ARIA labels, and keyboard navigation throughout

## Development setup

### Node version

**Use Node 16.** `react-scripts` 4.0.1 uses `postcss-safe-parser` which triggers `ERR_PACKAGE_PATH_NOT_EXPORTED` on Node 18+. The CI workflow pins `node-version: '16'`.

```bash
nvm use 16   # or: nvm install 16
```

### Install and run

```bash
npm ci            # install exact locked versions
npm start         # dev server at http://localhost:3000
npm test          # Jest / React Testing Library (watch mode)
npm run build     # production build → ./build/
```

## Architecture

All application code lives in a single file: **`src/index.js`**. Key classes and functions:

| Symbol | Purpose |
|---|---|
| `MultiRoundCribbageGame` | Root React component; holds cross-round scores, multiplayer state |
| `CribbageGame` | One round of play; owns deck, grid layout, turn logic, CPU, peer sync |
| `CardGrid` | Renders the 5×5 table, row/column scores, next-card display |
| `Card` / `FadeCard` | Leaf card components; `FadeCard` animates card placement |
| `Deck` | Button that ends a round and starts the next |
| `MultiplayerLobby` | Host/join overlay UI using `PeerSync` |
| `PeerSync` | Thin wrapper around `window.Peer` (PeerJS); `host()`, `join()`, `sync()` |
| `getNextMove(cardLayout, nextCard, cpuLevel)` | CPU AI – returns a grid index |
| `getNextMoveRatings(...)` | Evaluates score delta for every open cell |
| `softmax(values, alpha)` | Used for difficulty: higher `alpha` → stronger CPU |
| `scoreHand(hand)` | Sums `score15 + scoreFlush + scorePairs + scoreRuns` |
| `ratings.json` | Expected-value lookup table generated by the Jupyter notebook |

### CPU difficulty

`cpuLevel` (1–10) controls the `alpha` parameter passed to `softmax`. Level 1 is nearly random; level 10 always picks the objectively best cell.

### Multiplayer

PeerJS is loaded as a `<script>` tag in `public/index.html`, making `window.Peer` available. `PeerSync` wraps it with `host()` / `join()` / `sync()`. The host generates the initial shuffled deck, sends it to the joiner, and all subsequent game state is broadcast after every move via `peerSync.sync()`. Turn enforcement is handled by checking `this.props.isHost` against the `rowTurn` flag in game state.

## Coding conventions

- **Monolithic source**: keep all game logic and components in `src/index.js` unless the change is clearly self-contained enough to warrant a new file.
- **Class components** are used for stateful game objects (`CribbageGame`, `CardGrid`, `MultiplayerLobby`, `PeerSync`); functional components + hooks are used for simple leaf components (`Card`, `FadeCard`).
- **Inline styles** are common; Material-UI (`@material-ui/core`) is used for `Fade`, `Switch`, `Slider`, and `Typography`.
- **Accessibility**: every interactive element needs an `aria-label` or visible label; prefer semantic HTML (`<table>`, `<th scope>`, `<button>`, `<header>`, `<main>`). `@axe-core/react` runs automatically in development mode and will log violations to the browser console.
- **No TypeScript** – the project is plain JavaScript. Do not add TypeScript without discussion.
- **No new dependencies** without a clear reason – the dependency list is intentionally small.

## Important constraints

1. **Do not upgrade `react-scripts`** past 4.0.1 without a full migration plan; it would require significant changes and Node version updates throughout the project.
2. **`ratings.json` is generated data** – do not edit it by hand. Regenerate it using `generate_card_ratings.ipynb` if the scoring logic changes.
3. **PeerJS is loaded from CDN**, not bundled. Any change to the PeerJS version must be made in `public/index.html`.
4. **Card SVGs** in `public/cards/` are third-party public-domain assets – do not delete or rename them; the filename convention (`<RankLetter><SuitLetter>.svg`) is relied on by `convertCardToUrl()` in `src/index.js`.
5. **GitHub Pages** serves the app from the `gh-pages` branch – never push directly to that branch; let the CI workflow manage it.
